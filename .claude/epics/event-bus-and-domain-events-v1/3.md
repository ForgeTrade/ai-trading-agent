# Task: Domain Event Structures

## Description
Create the concrete event structures that represent all domain events in the trading system. These structs will carry the actual business data through the event bus and must be designed for both performance and correctness.

## Acceptance Criteria
- [ ] MarketData struct with fields: symbol, timestamp, sequence_number, session_id, open, high, low, close, volume
- [ ] OrderCommand struct with fields: symbol, side, quantity, order_type, price, timestamp, sequence_number, session_id
- [ ] ExecutionReport struct with fields: order_id, symbol, side, quantity, price, status, timestamp, sequence_number, session_id
- [ ] PositionUpdate struct with fields: symbol, quantity, avg_price, unrealized_pnl, timestamp, sequence_number, session_id
- [ ] RiskAlert struct with fields: alert_type, message, severity, timestamp, sequence_number, session_id
- [ ] ControlCommand struct with fields: command_type, parameters, timestamp, sequence_number, session_id
- [ ] All structs use rust_decimal::Decimal for financial fields (prices, quantities, PnL)
- [ ] All structs implement Serde derives for serialization
- [ ] Arc wrapping considered for hot path performance

## Technical Details
- Use rust_decimal::Decimal instead of f64 for all financial calculations
- Timestamp should be chrono::DateTime<Utc> for timezone safety
- Sequence numbers should be u64 for ordering guarantees
- Session IDs should be UUID for uniqueness across restarts
- Implement required traits: Debug, Clone, Serialize, Deserialize
- Consider using #[serde(rename_all = "snake_case")] for consistent JSON
- Add validation methods where appropriate (e.g., positive quantities)
