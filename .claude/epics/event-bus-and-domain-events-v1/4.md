# Task: Basic Channel Implementation

## Description
Implement the core InProcessBus using Tokio channels to provide reliable event delivery within a single process. This implementation will serve as the foundation for all event communication in the trading system.

## Acceptance Criteria
- [ ] InProcessBus struct implementing MessageBus trait
- [ ] HashMap storage for topic-to-channel mapping
- [ ] mpsc channels for lossless topics (OrderCommand, ExecutionReport, PositionUpdate, ControlCommand)
- [ ] broadcast channels for lossy topics (MarketData, RiskAlert)
- [ ] publish() method with topic validation and error handling
- [ ] subscribe() method returning BusStream for async iteration
- [ ] subscribe_all() method for subscribing to multiple topics
- [ ] Proper channel capacity configuration
- [ ] Thread-safe implementation using Arc<Mutex<>> where needed
- [ ] Graceful shutdown handling

## Technical Details
- Use tokio::sync::mpsc for lossless delivery (bounded channels with backpressure)
- Use tokio::sync::broadcast for lossy delivery (newer messages overwrite older)
- Channel capacities should be configurable but default to reasonable values (1000 for mpsc, 100 for broadcast)
- Implement proper error handling for channel send failures
- Use Arc<Mutex<HashMap<Topic, Sender>>> for thread-safe topic management
- Consider using a factory pattern for channel creation based on topic type
- Implement proper cleanup when all subscribers drop
